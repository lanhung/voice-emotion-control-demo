# Aura 情绪交互体验多元化规划

日期：2026-10-14；状态：体验规划，待原型验证。

范围：基于现有本地语音情绪 Demo，规划交互、反馈与验证路线；本轮交付仅为文档。

建议将 Aura 扩展为一个让用户**观察声音、表达感受、选择回应方式、创作与回看**的体验空间。首版优先组合「情绪镜子」「我来表达」「安静陪伴」三个能力，之后加入声音画布、表达练习和会话回看。液态光球与灯光矩阵继续作为共同的表现载体。

体验是否丰富，主要看用户能做多少种有意义的动作，以及系统能否给出可理解、可调整的回应。新增情绪词、声音和动画应服务于这些动作。以下研究发现与产品事实均附来源；功能、配色、时间参数和验收门槛是针对 Aura 的设计提案，需要通过原型和真实设备验证。

## 1 当前基础与体验机会

现状依据仓库的 [README](../../README.md)、[情绪定义](../../shared/emotions.ts)、[识别解析](../../server/sensevoice.ts)、[采集流程](../../src/hooks/useVoice.ts)、[音频处理器](../../src/audio/processor.ts)、[主页面](../../src/App.tsx)及两个可视化组件核对。

| 现有能力 | 当前边界 | 体验机会 |
| --- | --- | --- |
| 7 类情绪及 unknown | 每段返回一个映射后的标签；接口没有情绪概率、混合比例或连续情绪坐标 | 增加用户自述、混合表达和反馈选择，保留模型结果的来源 |
| 每 2.5 秒提交一段音频 | 识别反馈还需等待排队与推理；固定窗口可能截断字词 | 用已有即时音量反馈维持互动节奏，识别结果负责较慢的氛围变化 |
| 音量、峰值与静音信息 | 音量约每秒更新 20 次；没有现成音高、节拍、语速分析 | 同一种模型标签下，也能随声音强弱产生丰富形变 |
| 光球和 8 × 64 矩阵 | 主要输入为情绪、音量、活动状态和来源；已有色彩过渡 | 为形状、空间、节奏设计不同表现方式，两个载体共享交互规则 |
| 笑声、掌声、歌声等事件解析 | 解析器能接收相应标签，实际检出效果需要本机验证 | 在创作模式加入事件装饰；基础玩法不依赖每次都检出 |
| 手动情绪预览 | 当前只能在空闲时使用；录音后回到模型驱动 | 新增正式的「我的感受」入口，使用户能在录音中调整表达 |
| 连续转写、下载和清空 | 内存保留最近 120 条；记录时间目前是结果写入时间 | 建立按音频采集时间排列的会话轨迹，支持用户标注 |
| 监控与异常提示 | 技术监控默认展开 | 普通体验聚焦表达；开发模式保留完整监控能力 |

两个需要优先澄清的概念：

- 当前 `NEUTRAL` 显示为「平静」，建议在语音结果中改为「中性语调」或「未呈现明显情绪倾向」；「平静」仍可作为用户自述和灯效名称。声学中性不能直接证明用户心情平静。
- 模型线索、用户自述、反馈目标分别回答「这段声音被怎样分类」「我觉得自己怎样」「我希望界面怎样回应」。三者可以不同，不能互相覆盖成同一条识别事实。

## 2 研究与案例带来的设计依据

### 2.1 研究文献

| 来源 | 研究支持的结论 | 对 Aura 的设计启发与适用边界 |
| --- | --- | --- |
| [R1 Russell 1980 情绪环形模型](https://pdodds.w3.uvm.edu/research/papers/others/1980/russell1980a.pdf) | 以愉悦程度与唤醒程度组织情绪体验及情绪概念的关系 | 用「不愉快—愉快」「低活跃—高活跃」帮助用户手动表达；二维位置只是交互入口，无法穷尽全部情绪含义 |
| [R2 Cowen 等 2019 非语言发声研究](https://bsil.studentorg.berkeley.edu/wp-content/uploads/2019/01/CowenEtAlAmPsych.pdf) | 研究中的听者对短促非语言发声的判断呈现至少 24 种情绪意义，并存在连续过渡 | 支持探索笑声、哼唱和混合表达。研究采用美国英语使用者的判断，主要材料来自实验室；24 类不是 SenseVoice 的能力清单，也不是中文用户真实心情的检测结果 |
| [R3 Höök 2009 情感交互循环](https://www.csd.uoc.gr/~hy469/files/panels/hook_2009.pdf) | eMoto、Affective Diary 等案例强调身体行动、系统回应与用户自主赋予意义；用户会将色彩和形状用于设计者未预设的表达 | 设计「发声—看到变化—主动调整—再次表达」的循环，让用户拥有解释权；这些案例提供设计依据，不构成 Aura 有效性的实验验证 |
| [R4 Palmer 等 2013 音乐与颜色关联](https://palmerlab.berkeley.edu/pdf/PalmerSchlossXuPrado-Leon%282013%29.pdf) | 在美国、墨西哥参与者与所选古典音乐材料中，音乐和颜色的情绪关联有系统联系 | 声音、颜色、运动可围绕一致的表达组织；保留个人配色。该结果不证明某个颜色能改变心情，也不能确定所有文化中通用的情绪色表 |
| [R5 Amershi 等 2019 人工智能交互指南](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf) | 指南覆盖能力说明、纠正、关闭、不确定时收缩服务、谨慎适应及全局控制 | 提供「我的感受不同」「只看声音变化」「停止跟随」「恢复默认」等操作，保证反馈可控且容易恢复 |

据此采用一个组合：**少量易懂的情绪词 + 可选的连续自述 + 多种表现方式 + 用户控制**。研究允许我们提出更丰富的表达入口，但每一种映射仍需由目标用户验证。

### 2.2 可借鉴的产品机制

| 案例及官方来源 | 可观察的机制 | 在 Aura 中的转化 |
| --- | --- | --- |
| [R6 Apple State of Mind](https://support.apple.com/en-mt/guide/watch/apd7de0f5610/watchos) | 区分当下情绪和整日心情；用户主动选择感受，并可补充描述词及影响因素 | 首版仅记录本次会话的当下表达，补充词可跳过；不把几秒语音汇总成全天心情 |
| [R7 Google Blob Opera](https://blog.google/company-news/outreach-and-initiatives/arts-culture/create-festive-song-blob-opera/) | 用户控制音高、元音，角色即时响应并形成可保存的作品 | 让声音成为创作动作，给用户可完成的小作品。借鉴即时反馈与低门槛创作；它并非情绪识别产品 |
| [R8 Endel](https://endel.io/) | 官方区分随输入变化的持续声景，以及具有开始、中间、结束阶段的定时场景 | 为陪伴设计有起止的短体验；声音作为可选输出。此处借鉴产品结构，不引用其健康或效率宣传作为效果证据 |

### 2.3 能力和表现约束

[SenseVoice 官方模型卡 R9](https://huggingface.co/FunAudioLLM/SenseVoiceSmall)说明了语音识别、情绪识别与声音事件检测能力，也说明声音事件分类相较专用模型存在差距。Aura 的可交付能力以当前本地接口和实测为准，尤其不能把其他模型或论文的能力直接算到当前 Demo 上。

[W3C 动画交互说明 R10](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions)支持关闭非必要的交互动画。新增效果统一遵循减少动态偏好，并提供静态表现；情绪信息同时通过文字、形状或纹理呈现。

## 3 体验结构

建议将用户入口组织为三个意图，回看作为会话结束后的自然出口：

| 用户意图 | 主要体验 | 默认反馈 | 用户下一步动作 |
| --- | --- | --- | --- |
| 我想表达 | 情绪镜子、我来表达 | 声音线索与用户选择共同形成视觉表达 | 调整感受、增加描述词、选择反馈方式 |
| 我想待一会儿 | 安静陪伴 | 稳定、低刺激的视觉节奏 | 调整节奏、静音、暂停、结束 |
| 我想玩声音 | 声音画布、表达练习 | 声音与形态之间清晰的动作反馈 | 变换声音、对比、保存作品 |
| 我想看看刚才 | 会话回看 | 采集时间上的声音线索与个人标注 | 修订说明、选取片段、导出或清空 |

首版只呈现前两个入口。灯效载体选择独立于体验意图：光球、矩阵是同一套交互的两种显示方式。后续功能按需展开，避免首页同时出现大量模式按钮。

核心体验链路：

**选择意图 → 发声或手动表达 → 立即看到动作反馈 → 接收语音线索 → 调整表达或反馈 → 结束与回看。**

## 4 八个体验方向

### 4.1 情绪镜子 P0

**场景：** 用户说一句普通的话，想直观地看见自己的声音如何变化。

- 音量驱动光球的收缩、展开或矩阵光带宽度，保持即时响应。
- 每个有效识别结果更新语音线索；色彩与形态以连续过渡呈现，弱声、强声和停顿仍有不同表现。
- 新结果到达前显示「声音正在变化，语音线索稍后更新」。结果表达为「这段声音的线索：愉悦」，避免直接给用户定性。
- 用户可选择「只看声音变化」，保留声学互动并隐藏情绪标签。
- 标签旁提供「我的感受不同」，进入正式自述流程。

**示例：** 模型连续输出中性标签时，轻声让光带变窄、增强语气使形态展开、停顿使运动收束。丰富度来自真实声音变化，标签保持原结果。

**完成标准：** 连续中性标签也能形成可辨的动作反馈；用户能找到自述入口；unknown、静音和模型离线分别有明确状态。

### 4.2 我来表达 P0

**场景：** 用户觉得模型理解得不够准确，或想表达「有点紧张，也有点期待」。

- 提供二维感受面板，也提供同等功能的两个滑杆，支持键盘和触屏。
- 默认展示少量常用词；扩展词可包含安心、期待、疲惫、烦躁、好奇等，明确标为「我的表达」。这些词不进入模型识别结果清单。
- 允许最多选择两个描述词。用双层纹理或两股光流表达并存；如提供混合滑杆，名称为「表现比例」，不显示成识别概率。
- 录音中可切换至自述驱动，语音仍继续转写。界面明确提示「当前跟随我的表达」，并提供「回到语音跟随」。
- P0 支持调整当前表达；历史片段标注随 P1 回看加入，届时保留原始语音标签与个人标注；这些操作不会自动训练模型。
- 未授权麦克风或模型不可用时，仍能完成手动表达。

**控制范围：** 当前表达默认持续到用户切换来源或结束会话；它不会自动重写此前的识别记录。历史片段标注仅作用于选中的片段。

**完成标准：** 不开麦也能完成一次表达；录音中的手动选择不会被下一次模型结果抢走；用户能区分个人描述与模型线索。

### 4.3 安静陪伴 P0

**场景：** 用户希望停留片刻、缓一缓，或需要一个不抢注意力的视觉环境。

提供三个反馈策略，均由用户主动选择：

| 策略 | 反馈行为 | 典型使用 |
| --- | --- | --- |
| 跟随声音 | 在用户设置的强度范围内响应音量与语音线索 | 观察自己的表达 |
| 柔和陪伴 | 保持较低亮度、较小形变和更平稳的运动，允许有限的声音响应 | 说话时希望环境安静一些 |
| 固定氛围 | 保持用户选择的颜色与节奏，录音可独立开关 | 不希望界面继续随识别变化 |

可以选择 1 分钟或 3 分钟，也可随时结束。流程为「选择节奏—停留—自行结束或到时收束」；提示保持简短，如「可以说话，也可以安静待一会儿」。如加入呼吸般的视觉节奏，它是可调节的视觉引导，不宣称正在测量用户呼吸。

模型识别到愤怒或低落时，继续执行用户选择的策略。是否切换到柔和反馈由用户决定。结束时可选填「这种反馈适合我吗」，不把模型标签变为愉悦当作成功条件。

**完成标准：** 进入和退出均明确；支持无麦克风使用；固定氛围不会被识别结果覆盖；用户能控制亮度、动态程度和时长。

### 4.4 声音画布 P1

**场景：** 用户用说话、哼声、笑声等创作一段可保存的视觉作品。

基础玩法使用已有的音量和时间信号；声音事件作为模型返回后的附加装饰：

| 输入 | 光球表现提案 | 矩阵表现提案 | 依赖 |
| --- | --- | --- | --- |
| 轻声、强声、停顿 | 细纹、展开、收束 | 细线、宽带、留白 | 已有音量和静音信息 |
| 笑声事件 | 局部小泡泡 | 稀疏跳跃光点 | 事件检出实测 |
| 掌声事件 | 一次外扩波纹 | 一次向两侧扩散 | 事件检出实测；不作为即时节拍 |
| 歌声事件 | 延长流动尾迹 | 连续光带 | 事件检出实测；不代表准确音高 |
| 拖动或键盘操作 | 控制方向、纹理密度 | 控制光带位置 | 新增手动控制 |

一次作品建议为 20–30 秒。用户可更换主题、重做并保存静态作品卡；首期不保存原始录音。动态图导出可在静态作品体验验证后再评估。

每种事件需要冷却与去重，防止同一声音跨窗口重复触发。哭声、咳嗽等不默认触发庆祝动画。没有检出事件时，音量画布仍然完整可玩。

**完成标准：** 不依赖某个特定情绪标签也能完成作品；用户能说明至少两种声音动作对应的视觉差异；导出前可预览内容。

### 4.5 一句话的不同表达 P1

**场景：** 用户用不同方式说同一句话，探索语气与视觉表现的关系。

建议脚本为「这件事终于完成了」：先按自己的习惯说，再从轻松、郑重、惊喜中选两种表达，各说一轮，共三轮。每次录制单独成一轮，结束后完成剩余识别，避免固定窗口把不同轮次混在一起。

三张对比卡并排展示用户选定的表达意图、音量变化、视觉缩略图和实际模型标签。用户可标注「更接近我想表达的感觉」，可以重试或跳过。即使三次都返回中性，也如实显示；不给“情绪正确率”或心理健康分数。

首期对比视觉轨迹与文字记录。若要听原声回放，需要另行设计录音保存、删除和导出的完整流程。

**完成标准：** 每轮边界清楚；用户意图与识别结果独立展示；所有标签相同仍可完成体验；不要求用户强行演绎负面情绪。

### 4.6 会话回看 P1

**场景：** 用户结束一段表达后，想看看何时有停顿、何时声音增强，以及哪些片段值得留下。

- 使用横向「情绪河流」表示当前保留范围：时间向前延伸，宽度表示声音强弱，颜色表示该时段的线索或表达来源。
- 模型线索与用户自述使用不同标记；同一时段可展开并列查看。艺术配色不替代原始标签。
- 时间轴依据音频采集起止时间构造，推理完成时间用于延迟信息。不能直接拿目前的 `timestamp: Date.now()` 当说话时刻。
- 静音、无结果和记录被截断的区间明确留白；不将上一条情绪延长填满空白。
- 允许添加「这里我其实是在开玩笑」等备注。导出前选择是否包含文字，默认作品卡仅含视觉和用户主动选择的说明。
- 首期仍采用最近 120 条记录的上限，显示实际保留时间范围；在连续有效的完整窗口下约覆盖 5 分钟，存在静音跳过时跨度会更长。不得把被截断的数据称为完整会话。
- 轨迹保存每窗音量摘要与有限的个人操作记录，不保留音频样本。语音会话的附加轨迹随保留区间裁剪；纯手动会话暂定只保留最近 5 分钟，并显示范围。

若展示占比，优先使用已保留且有效的音频时长作为分母，并明确统计范围；预览、静音、unknown 和用户自述单列。首版可先不展示占比，避免让艺术轨迹看起来像心理测量报告。

**完成标准：** 网络或推理变慢不会错置发声时刻；能识别来源与缺失区间；刷新、清空、截断和导出行为与说明一致。

### 4.7 可选声音回应 P1 后段

**场景：** 用户希望视觉之外，还有轻量的声音反馈或背景声景。

优先制作少量本地、许可明确的无歌词音色或环境声：柔和、轻快、开阔三种主题足以验证。由用户点击开启，声音与视觉强度分别可调；变化使用渐入渐出，开始播放前即可看到静音入口。

需要先解决扬声器播放被麦克风再次识别的问题。原型默认采用「说话时降低背景声」或「一轮结束后再回应」，测试耳机与扬声器两种场景。回声消除不能视为问题已解决。

**完成标准：** 无突然起音或音量跳升；声音关闭后视觉体验完整；播放自己的声景不会持续触发音乐事件并反向强化效果。

### 4.8 双人轮流共创 P2

**场景：** 两个人各表达一段，再共同制作一个视觉作品。

使用明确的「轮到 A」「轮到 B」按钮；每轮停止并处理完剩余片段后交接。展示两条独立轨迹，由两人分别确认要使用的片段，再合成作品。

当前没有说话人分离能力，因此先采用人工轮次；若两人同时说话，由参与者选择重录该轮。双人体验的目标是表达与共同创作，不推断关系质量、契合度或谁的情绪更健康。

**进入条件：** 单人创作和回看已验证，轮次隔离稳定，双方能够分别删除自己的片段。

## 5 视觉与反馈语言

### 5.1 从配色扩展到形态和行为

以下是候选表达语言，不是心理学标准映射；用户可改色，也可只使用形态区分。

| 表达主题 | 形态与运动 | 空间与纹理 | 适合的交互 |
| --- | --- | --- | --- |
| 平静、安心 | 缓慢扩张、圆润连续 | 较疏、边缘柔和 | 安静陪伴、自述 |
| 愉悦、期待 | 轻快上扬、局部绽放 | 明亮小点、开放空间 | 表达、声音画布 |
| 低落、疲惫 | 低速流动、较小振幅 | 较长尾迹、柔和层次 | 自述、镜子 |
| 愤怒、烦躁 | 有力的定向波动 | 局部较密、边缘清楚 | 镜子、表达练习；受用户强度上限约束 |
| 惊讶、好奇 | 一次展开后恢复 | 外扩层次、稀疏亮点 | 表达、探索 |
| 紧张、担心 | 小范围不规则变化 | 多层细纹 | 仅在允许动态时使用，柔和模式改为静态纹理 |
| 厌恶、排斥 | 局部收拢、向外让出空间 | 分离纹理 | 用户选择或对应语音线索 |
| 混合表达 | 两股运动并存 | 双层纹理 | 用户明确选择的两个描述词 |

正负感受拥有同等的可表达空间。低落不自动导向“修复”，愤怒不自动放大刺激。颜色、文字、速度、形状应有一致的表达方向，但允许用户改变个人含义。

### 5.2 即时反馈与会话走势

| 时间尺度 | 使用信息 | 首版策略 |
| --- | --- | --- |
| 快速动作反馈 | 已有约 20 Hz 的音量消息 | 收缩、展开、宽度等连续变化；浏览器收到音量消息至首次对应绘制，暂定 P95 ≤ 150 ms |
| 分段语音线索 | 2.5 秒窗口加排队及推理时间 | 每个有效结果更新，色形过渡初值 600–900 ms；等待期间保持声音响应 |
| 会话走势 | 已保留片段与个人标注 | 只表示已观察或已自述的数据，缺失区间留白 |

这些参数是原型起点。快速反馈指标不包含物理麦克风和系统驱动延迟，也不代表情绪识别能在 150 ms 内完成。首版在动画层平滑，不额外要求连续多个窗口标签相同才显示新结果；如后续增加历史平滑，需同时评估额外延迟与变化被掩盖的问题。

## 6 状态与控制规则

| 情况 | 用户看到的行为 | 数据处理要求 |
| --- | --- | --- |
| 尚未开麦 | 可预览、手动表达或进入陪伴 | 初始灯效不算作识别记录 |
| 已开麦，结果未到 | 声音动作反馈与等待提示 | 记录采集时间，不生成假标签 |
| unknown 或没有情绪标签 | 「暂时没有明确的语音线索」及基础声学反馈 | 保留 unknown，不自动补为平静 |
| 持续静音 | 动作渐缓、显示等待 | 识别时间轴留白；固定氛围可继续作为独立效果 |
| 标签短时来回变化 | 原始记录保留，视觉做连续过渡 | 变化次数可用于调参，不包装成模型置信度 |
| 自述与模型不一致 | 主视觉跟随用户选定来源，详情并列显示 | 保留原标签和个人标注 |
| 用户固定氛围 | 保持所选表现，转写按录音状态继续 | 固定氛围不进入模型结果字段 |
| 切换光球与矩阵 | 延续当前表达和强度 | 不重启录音，不重置来源 |
| 模型超时或断线 | 明确停止采集，保留可用的手动表达入口 | 不继续累积请求，区分旧结果和当前状态 |
| 减少动态或渲染降级 | 静态色块、纹理和文字 | 所有关键操作仍可使用 |

控制冲突的优先级为：**停止/静音等即时操作 → 当前用户选择的反馈策略 → 当前表达来源 → 具体渲染效果**。安全退出、低动态和用户强度上限作用于所有模式。

「结束体验」同时停止麦克风采集、计时和声音输出，再进入结束态；如允许陪伴继续运行，则单独提供「结束聆听」，明确它只关闭麦克风。处理停止前已采集的末段音频时，界面显示完成进度。

## 7 页面组织与一次完整体验

普通体验页面建议按以下顺序组织：意图入口、主视觉、当前来源与一句简短解释、主操作、可展开的表达面板、会话记录。设备和错误状态保持可见；RMS、请求队列和原始 JSON 等详细信息归入开发监控。

一段约 90 秒的首版演示可以这样展开：

1. 用户选择「我想表达」，可先手动拖动感受面板；开始聆听时再请求麦克风权限。
2. 用户说「今天有点累，不过事情终于做完了」。声音立即改变形态，语音结果稍后出现。
3. 用户选择「我的感受不同」，标注「疲惫 + 安心」，看到两种纹理并存，来源显示为「我的表达」。
4. 用户选择「柔和陪伴」，表现逐步收束；之后的识别结果继续记录，主视觉维持选择的策略。
5. 用户结束会话。P0 显示简单结束态与已有转写操作；P1 再加入会话轨迹、标注和作品卡导出。

这条路线让一次会话包含观察、表达、选择和结束，后续创作功能可以沿用同一组控件与状态规则。

## 8 落地顺序与工程影响

### 8.1 优先级与阶段产出

| 阶段 | 交付范围 | 依赖与规模判断 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 设计验证 | 三个核心能力的低保真原型、文案、光球和矩阵状态稿 | 小；可先使用纸面、静态原型和人工驱动效果 | 用户理解来源、找到纠正和停止入口，并能区分三个能力 |
| P0 | 情绪镜子、我来表达、安静陪伴；来源与覆盖规则；采集时间基础 | 中；以现有模型和本地信号为基础，需要前端状态与表现层调整 | 首版验收场景通过，真实麦克风体验未退化 |
| P1 前段 | 声音画布、会话回看 | 中；依赖时间轨迹、事件实测、导出与表现参数 | 用户能独立创作、回看和删除；延迟不造成明显误解 |
| P1 后段 | 表达练习、可选声音回应 | 中到大；依赖轮次管理、音频播放和回授验证 | 轮次正确，声音输出无自激循环，用户能随时关闭 |
| P2 | 双人轮流共创；按实际需求评估实体灯光 | 大；需独立梳理多人状态或硬件适配 | 单人核心体验稳定，有明确的目标场景与需求 |

规模为相对判断，不是工期承诺。实施顺序建议为：来源、控制规则与采集时间基础 → P0 三项能力 → 回看与创作 → 表达练习、声音输出 → 多人扩展。完整回看界面在 P1 实现。

### 8.2 后续实现可能涉及的边界

| 现有位置 | 计划调整方向 |
| --- | --- |
| `shared/emotions.ts` | 将模型标签、个人描述、反馈目标和视觉主题分开建模；扩展表达词不改变识别标签的含义 |
| `server/sensevoice.ts` | 保留原始标签与声音事件；首版主要复用现有解析，不填补模型没有给出的概率 |
| `src/hooks/useVoice.ts`、`src/audio/processor.ts` | 保留采集起止时间、会话及片段标识；区分信号更新、结果到达与用户操作 |
| 新的交互状态层 | 管理意图、表达来源、覆盖范围、反馈策略和结束状态，避免全部堆入录音逻辑 |
| `src/components/visualization.ts` 与两个渲染器 | 接收统一的表现参数；光球与矩阵共享语义，分别实现形状、空间和动态 |
| `src/App.tsx`、`src/styles.css` | 调整体验入口、表达控件、结束态和响应式布局 |
| `src/components/MonitorPanel.tsx`、`shared/monitoring.ts` | 记录来源切换、覆盖、反馈策略、绘制时刻与回看边界；便于查清效果从哪里来 |
| 后续回看与导出模块 | 管理有限的会话轨迹、用户标注、内容预览与导出范围 |

当前可复用的输入包括模型标签、声音事件、音量、峰值和静音信息。音高、稳定节拍、语速、连续情绪坐标、说话人区分与自由对话都需要新增能力和独立验证，不作为 P0 依赖。首版反馈文案可采用确定性的短句，无需接入对话模型。

实体灯光、跨日心情报告和账号同步留在后续需求评估中。当前「本地处理、录音不落盘、记录仅驻留内存」的体验约定应延续；若未来加入持久化或录音回放，再为其单独设计用户可见的保存与删除流程。

## 9 验证计划

### 9.1 先验证交互，再验证真实识别

第一轮招募 8–12 名目标用户，每人约 20–30 分钟；覆盖普通话与部分不同口音、不同音量习惯，以及桌面和手机场景。样本用于发现可用性问题，不用于证明情绪识别准确率或健康效果。

对比 A 为当前「预览 + 跟随识别」体验，B 为 P0 提案。交替安排体验顺序，尽量控制设备和任务一致。设计阶段可以使用人工控制的原型反馈，并在测试说明中明确它是模拟；实现后必须用真实麦克风链路重新验证，尤其观察延迟和中性标签持续输出的情况。

| 任务 | 观察内容 |
| --- | --- |
| 不开麦表达「紧张又期待」 | 能否找到自述、选择两个词并理解来源 |
| 正常说话，再主动纠正一个不合适的标签 | 纠正入口是否明显，下一次结果是否破坏选择 |
| 选择柔和陪伴后提高说话音量 | 是否理解强度上限与反馈策略的关系 |
| 切换光球与矩阵，再结束聆听 | 能否保持上下文、快速停止并理解结束状态 |
| P1 创作一张声音作品并回看 | 能否说明动作与效果的关系、找到自己的标注 |
| 经历静音、unknown 或模型离线 | 是否将等待和缺失误认为被系统判定为某种心情 |

### 9.2 暂定通过标准

| 指标 | 暂定门槛与测法 |
| --- | --- |
| 来源理解 | 至少 80% 的参与者能正确区分模型线索、个人表达和效果预览；同时报告实际人数 |
| 核心操作完成 | 至少 80% 可无主持人帮助完成自述、切换反馈和结束；同时报告实际人数 |
| 用户控制感 | 7 分量表中位数达到 5 分，并结合失败任务分析原因 |
| 表达丰富度 | 多数用户能指出至少两种可主动操作的表达方式，并举出它们的差别 |
| 声学反馈延迟 | 在约定的目标设备上，音量消息到对应绘制的 P95 ≤ 150 ms；记录设备条件 |
| 识别等待 | 分开记录窗口等待、排队、推理和呈现耗时；P0 新增处理不引入额外的完整窗口等待 |
| 模式与覆盖可靠性 | 所有约定状态用例通过；不存在下一条模型结果抢回手动控制的问题 |
| 感官可用性 | 减少动态、关闭声音、键盘操作后，关键任务仍能完成 |

门槛是团队的初始决策标准；小样本报告使用人数、分布和观察记录，避免用百分比制造过度精确的结论。用户自述可以评估「系统反馈是否符合自己的表达」，但不能单独证明声学分类器的客观准确率。

### 9.3 后续实现验收场景

- 连续多段 `NEUTRAL`：声音强弱仍有明显反馈，模型记录保持中性。
- 单段 unknown、连续静音、无语音的声音事件：来源和状态清楚，不补造情绪。
- 自述覆盖期间连续返回不同标签：主视觉不抢回控制；恢复跟随后使用明确的当前结果或等待状态。
- 高低音量切换、静音门限附近、不同麦克风：视觉不因微小噪声失控，也不要求用户大声喊叫。
- 推理变慢、队列积压、停止后末段返回：沿用可解释的完成/失败流程，结果不会进入错误轮次。
- 录音中切换载体、进入/退出沉浸、窗口隐藏：状态一致，资源使用正常。
- 会话超过 120 条、跨次录音、刷新和清空：保留范围、会话归属与删除范围明确。
- 低动态、键盘、触屏、WebGL 不可用：仍可表达与停止。
- 声音输出开启后的耳机/扬声器场景：无持续回授触发；关闭后立即停止可听输出。

本轮只审查规划文档与引用；上述用户研究、性能指标和功能场景均属于后续工作，不是已经完成的测试结果。
